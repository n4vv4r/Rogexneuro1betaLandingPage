# NAVI L2 — motor generativo neuromórfico (host)

**No es un LLM.** No hay embeddings float, no hay KV-cache O(N²), no hay
PyTorch. Es memoria asociativa hiperdimensional + un estado recurrente
entero O(1) por token.

L1 (`kernel/navi/`, Q₆, ~480 B) sigue siendo el atractor de 6 bits.
L2 vive aquí (`NAVI_AI_SNN/l2/`) hasta que merezca un binario de userland.

```bash
cd NAVI_AI_SNN && make l2
```

## Flujo (token → predicción)

1. **Tokenizer C.** Palabras clave, tipos, `kernel_main`, operadores.
   Identificadores fuera de tabla → `<ident>`. Números → `<num>`.

2. **Encoder HDC (D = 1024).** Cada id de token genera un hipervector
   bipolar determinista (xorshift, semilla `MONA`). No se guarda una
   tabla de 1024×V floats.

   - **Bind:** `A ⊕ B` (XOR). Involutivo: `(A ⊕ B) ⊕ B = A`.
   - **Shift:** rotación de 1024 bits (posición / orden).
   - **Bundle:** suma ±1 en un acumulador `int16` y umbral al signo (mayoría).

   Clave de bigrama:

   ```
   key = hv(t) ⊕ rot(hv(t-1), 1)
   ```

3. **RWKV ternario / LIF.** Proyecciones `W_k, W_v, W_r` con
   `W ∈ {-1,0,1}` empaquetadas a 2 bits. Producto = suma/resta/nada.

   ```
   k,v,r = W_* · x_hdc          # entero, sin mul
   mem   = (7/8) mem + k        # leak racional
   spike = +1 / -1 / 0          # |mem| ≥ Vth
   S     = (7/8) S + spike·sign(v)   si r ≥ 0
   ```

   `S ∈ ℤ¹⁶` de dimensión H=32. Memoria de contexto **O(H)**, no O(N²).
   Los pesos **no están entrenados**: mezclan el último patrón. El
   conocimiento útil está en los prototipos HDC.

4. **Decisión.**

   ```
   score(c) = 4 · sim(key, proto_c) + sim(mix_RWKV, proto_c)
   next     = argmax_c score(c)
   ```

   `sim` = bits iguales (XNOR). Aprender es `proto[next] ← bundle(proto, key)`.

## Qué demuestra la demo

Tras enseñar un corpus mínimo de C:

```
void kernel_main   →   (
```

y al alimentar el token predicho:

```
void kernel_main ( void ) { return <num> ;
```

Eso es **completado de n-gramas enseñados**, no “entiende el kernel”.
Si el prompt no está en el corpus, la predicción no tiene por qué ser C válido.

## Saturación

K=4 átomos fijos por clase. Bundle leaky 7:1 en la pila (sin `int16[D]`
persistente). Un contexto nuevo se une al átomo cercano o **pisa el más
débil**. `sizeof` no se mueve con el corpus (medido: 66 352 B antes y después
de 6 420 tokens de cabeceras rxOS).

## Huella

| Cosa | Tamaño |
| --- | --- |
| `sizeof(navi_l2_t)` | **66 352 B** (plano; no crece) |
| L1 Q₆ en el kernel | ~480 B |
| Un LLM 7B int4 | ~4 GiB |

Aún cabe “menos que una calculadora de escritorio” (15–40 MiB) si no
añades un banco de pesos entrenado de decenas de megas. El día que L2
tenga un fichero de pesos de 40 MiB, el eslogan hay que volver a medirlo.

## Qué no es

- No genera código C nuevo que no haya visto como n-grama.
- No sustituye a `navi calc` ni al atractor Q₆.
- No entra en el kernel en esta fase (L2 es host / futuro userland).
